# Site Acceptance Test (SAT)

Приёмка на объекте с реальными (или согласованными) устройствами Modbus и SCADA.
Выполняется после FAT. Не заменяет лабораторные автотесты.

## Предусловия

- [ ] FAT протокол подписан (или отклонения явно перенесены)
- [ ] Актуальная карта `*.modbusproj.json` объекта, не demo-plant
- [ ] Согласованы VLAN/firewall: TCP 502 к устройствам, 4840 к SCADA
- [ ] Security policy UA согласована (None только в изолированном lab-VLAN)

## Сценарии объекта

- [ ] **SAT-1** `opc-map validate` и `doctor` на боевой карте
- [ ] **SAT-2** Опрос всех poll groups: нет систематических timeout на healthy устройствах
- [ ] **SAT-3** Выборочная сверка 5–10 тегов с локальным HMI/панелью прибора
- [ ] **SAT-4** SCADA Read + Subscription на согласованном клиенте
- [ ] **SAT-5** Запись уставок только по списку writable; откат/подтверждение с объекта
- [ ] **SAT-6** Плановый обрыв линка (отключить патч-корд / disable port): Quality деградирует предсказуемо
- [ ] **SAT-7** Восстановление линка без ручного рестарта шлюза
- [ ] **SAT-8** Нагрузка объекта: число тегов и клиентов в пределах [09-scalability.md](../09-scalability.md)
- [ ] **SAT-9** Время работы ≥ согласованного soak (например 8 ч) без утечки RSS и без restart
- [ ] **SAT-10** Резервное копирование карты и (если есть) SQLite historian
- [ ] **SAT-11** Контакт/эскалация: как снимать frame log и `--log-file` для вендора

## Безопасность площадки (62443-практика, не сертификат)

- [ ] Учётные данные UA / сертификаты не в git и не в чате
- [ ] Studio на площадке — read-only к runtime
- [ ] Нет ненужного открытия 4840 в корпоративную сеть
